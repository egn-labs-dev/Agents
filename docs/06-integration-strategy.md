# Стратегія Об'єднання Проєктів (Integration Strategy)
## Enterprise AI Shield for Logistics

Цей документ фіксує детальний архітектурний план синергії між проєктом **DevOps AI Assistant (`gcp-ai-agents-lab`)** та платформою **Zero Trust Dispatch (`LOG`)**. Об'єднання створює суверенну Enterprise-платформу з безпрецедентним рівнем безпеки даних та незмінним аудитом.

---

### 🛡️ 1. Двостороння броня безпеки (Cross-Pollination)
Створення двох кіл оборони на базі існуючих напрацювань обох проєктів.

*   **Lab ➡️ LOG (Pydantic Shield):** Перенесення FastAPI Pydantic-валідаторів з регулярними виразами (захист від Prompt Injection) у маршрутизацію проєкту `LOG`. Мета — відсікати спроби маніпуляції AI (наприклад, "ігноруй правила ADR") на кордоні бекенду за 0.2 секунди до виклику Gemini.
*   **LOG ➡️ Lab (Data Scrubber):** Перенесення алгоритмів маскування PII з `LOG` у клієнт `gemini_client.py` DevOps-бота. Мета — автоматична заміна паролів, токенів та персональних даних у логах розробників перед відправкою до LLM (захист від витоку інфраструктурних таємниць).

### 📚 2. Vertex AI RAG для Логістики
Інтеграція підходу Vertex AI Agent Builder з проєкту Lab у доменну область LOG.

*   **Реалізація:** Створення нового GCP Data Store (`logistics-compliance-store`).
*   **Контент:** Завантаження офіційних PDF-довідників (ADR, митні кодекси, фітосанітарні норми).
*   **Результат:** AI-диспетчер проєкту `LOG` асинхронно звертається до Data Store при запитах про правила перевезень. Гарантована 100% точність юридичних відповідей без галюцинацій.

### 📝 3. GCP Cloud Logging (Незмінний Enterprise-аудит)
Задоволення жорстких вимог B2B комплаєнсу (GDPR, ISO/IEC 27001).

*   **Реалізація:** Перенесення FastAPI Logging Middleware з Lab у `LOG`.
*   **Результат:** Всі критичні дії AI-диспетчера та зміни Vault фіксуються безпосередньо у Google Cloud Logging Bucket з політикою Retention (Locked). Це фізично унеможливлює видалення чи модифікацію логів адміністраторами БД, забезпечуючи ідеальні докази для юридичних аудитів.

### 🤖 4. DevOps-бот як SRE-Ангел для інфраструктури LOG
Замикання екосистеми: використання DevOps-асистента для моніторингу проєкту Zero Trust Dispatch.

*   **Інцидент-менеджмент:** Налаштування Webhook від Google Cloud Monitoring. У разі падіння компонентів (наприклад, HashiCorp Vault), бот миттєво отримує алерт.
*   **Автоматична діагностика:** Бот робить RAG-запит по завантаженій документації `LOG` (архітектура, `docker-compose.prod.yml`) та видає в робочий чат інженерів готові команди для виправлення (наприклад, перевірити токени або збільшити ліміти пам'яті).
*   **Результат:** Скорочення часу відновлення (MTTR) з годин до хвилин.

**Наступний крок (на завтра):** Розпочати інтеграцію з Пункту 1 — впровадження Pydantic-захисту від Prompt Injection у проєкт `LOG` (папка `app/api/` чи `app/schemas/`).
